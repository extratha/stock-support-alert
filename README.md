## สูตรคำนวณแนวรับ

ใช้ข้อมูลแท่งเทียนรายวัน (~260 แท่ง ≈ 1 ปี) เฉพาะ **session ที่ปิดแล้ว** (แท่งวันนี้ที่ยังไม่จบถูกตัดทิ้ง)
แล้วรวบรวมแนวรับ **เชิงโครงสร้าง** 3 วิธี กรองเฉพาะระดับที่ **ต่ำกว่าราคาปิดล่าสุด** ก่อนจัดลำดับ

| วิธี | สูตร | บทบาท |
|---|---|---|
| **Swing Low (โซน)** | จุด low ที่ต่ำกว่า low ของ 5 แท่งซ้าย-ขวา (fractal) ภายใน 250 แท่ง แล้ว**รวมจุดที่ห่างกันไม่เกิน 1.5% เป็นโซนเดียว** นับว่าราคาเคยเด้งในโซนนั้นกี่ครั้ง · ระดับ = ขอบบนของโซน (ถ้าราคาอยู่ในโซนแล้ว ใช้ขอบล่าง) | ราคาที่ผู้ซื้อเคยเข้ามาจริง ยิ่งเด้งหลายครั้งยิ่งมีน้ำหนัก |
| **Moving Average** | SMA 50 และ SMA 200 ของราคาปิด | แนวรับเชิงแนวโน้มระยะกลาง/ยาว — MA200 คือเส้นที่สถาบันดู |
| **Fibonacci Retracement** | ขาขึ้นล่าสุด: high สูงสุดใน 120 แท่ง และ low ต่ำสุดก่อนหน้า high นั้น → level = High − r·(High−Low), r = 38.2%, 50%, 61.8% | จุดพักตัวมาตรฐานของแนวโน้มขาขึ้น (ข้ามไปถ้า range < 10% หรือไม่มีขาขึ้น) |

**เอา Pivot Point รายวันออกแล้ว:** Pivot คำนวณจากแท่งเทียนของเมื่อวานแท่งเดียว จึงเปลี่ยนทุกวันและเลื่อนตามราคาลงไปเรื่อย ๆ — ราคาวันนี้ก็คือ "แนวรับ" ของเมื่อวาน ซึ่งแปลว่าไม่มีแนวรับจริง และ backtest พบว่าการแตะ Pivot ไม่ได้ดีกว่าการซื้อวันสุ่ม

### การจัดระดับความสำคัญ

| ระดับ | วิธีที่เข้าเกณฑ์ | กติกาเลือก |
|---|---|---|
| **แนวรับแรก** (Minor) | Swing Low, MA50, Fib 38.2%, Fib 50% | อันที่ **ใกล้ราคาปัจจุบันที่สุด** |
| **แนวรับถัดไป** (Intermediate) | Swing Low, Fib 50%, MA50, Fib 38.2% | อันที่สูงสุดที่ยังต่ำกว่า Minor อย่างน้อย 1% |
| **แนวรับสำคัญ** (Major) | MA200, Fib 61.8% (สำรอง: โซน Swing Low ที่เด้ง ≥2 ครั้ง) | อันที่สูงสุดที่ยังต่ำกว่า Intermediate อย่างน้อย 1% |

**ทำไมออกแบบแบบนี้**
- *ใช้เฉพาะระดับที่ไม่ขยับตามราคา* ราคาที่เคยเด้งจริง, ค่าเฉลี่ยระยะยาว, และ retracement ของขาขึ้นที่จบไปแล้ว
- *ทุกระดับห่างกันอย่างน้อย 1%* (วัดจากขอบล่างของโซน) กันไม่ให้ 3 ระดับซ้อนทับจนแจ้งเตือนซ้ำซ้อน
- *ระดับที่อยู่เหนือราคาถูกตัดออก* (เช่น หุ้นหลุด MA200 แล้ว เส้นนั้นกลายเป็นแนวต้านจึงไม่ถูกใช้)
- ถ้าวิธีหนึ่งไม่มีข้อมูล (หุ้นเพิ่ง IPO ไม่มี MA200) ระบบจะหยิบระดับที่ใกล้สุดจากวิธีอื่นมาแทน

### แนวรับเคย "รับได้" จริงไหม (ใต้แต่ละระดับบนหน้าเว็บ)
ทุกวันหลังคำนวณแนวรับ ระบบเล่นวิธีคำนวณปัจจุบันซ้ำกับราคาย้อนหลัง ~5 ปีของหุ้นตัวนั้น ทีละวันโดยไม่แอบดูอนาคต ([`src/lib/support/track.ts`](src/lib/support/track.ts)) ทุกครั้งที่ราคาแตะระดับ จะ**จำราคาระดับนั้นไว้** แล้วดูว่าเกิดอะไรก่อนภายใน 20 วันทำการ:
- **รับได้** = ราคาปิดเด้งขึ้น ≥3% จากระดับ · **หลุด** = ราคาปิดต่ำกว่าระดับ (หรือขอบล่างของโซน) เกิน 3% · ไม่เกิดทั้งสอง = ไม่ชัด
- **ตัวเปรียบเทียบ:** เอาระยะห่างจากราคาปิดวันก่อนเท่ากันไปวางเป็น "ระดับมั่ว" ในทุกวันอื่นของหุ้นตัวเดียวกัน แล้วใช้กติกาเดียวกัน ถ้าแนวรับรับได้ไม่มากกว่าระดับมั่ว ก็ไม่ได้มีความหมายพิเศษ (ทดสอบกับราคาสุ่มแบบ random walk แล้วได้ค่าเท่ากันตามที่ควร — ดู `track.test.ts`)
- ถ้าระดับหลุดภายใน 30 วันที่ผ่านมา การ์ดจะแสดง "แนวรับ $X หลุดเมื่อ …" แทนที่จะเปลี่ยนเป็นระดับใหม่เงียบ ๆ

โค้ดอยู่ที่ [`src/lib/support/`](src/lib/support) (pure functions มี unit test ครบ)

> ⚠️ แนวรับเป็นเครื่องมือประกอบการตัดสินใจ ไม่ใช่คำแนะนำการลงทุน

## กติกาการแจ้งเตือน

**แจ้งเตือนเฉพาะ "แนวรับสำคัญ"** (ค่าเริ่มต้น) เพื่อลดจำนวนข้อความ (≈ 1 ข้อความต่อเดือน) — backtest ยังไม่พบว่าระดับใดดีกว่าการซื้อวันสุ่มอย่างมีนัยสำคัญ ดูหัวข้อ Backtest — ตั้ง `ALERT_TIERS=minor,intermediate,major` ถ้าต้องการแจ้งทุกระดับ ระดับอื่นยังแสดงบนหน้าเว็บและในคำสั่ง "ขอแนวรับ" ตามปกติ

State machine แยกตาม **(หุ้น, ระดับ)** — ดู [`src/lib/alerts/evaluate.ts`](src/lib/alerts/evaluate.ts)

- **แตะ** = ราคา ≤ แนวรับ × 1.003 (รวมกรณีหลุดลงไปแล้ว)
- แจ้งเตือนแล้ว → ระดับนั้น "หยุดแจ้ง" จนกว่าราคาจะ **เด้งขึ้นเหนือแนวรับ +1%** จึง "พร้อมแจ้งใหม่"
- แตะ **คนละระดับ** → แจ้งได้ทันที (state แยกกัน) · แตะ **ระดับเดิมซ้ำหลังเด้งขึ้นไปแล้ว** → แจ้งได้อีก ไม่จำกัดครั้ง/วัน
- Cooldown ขั้นต่ำ 60 นาทีต่อ (หุ้น, ระดับ) กัน noise
- หลายระดับที่ trigger พร้อมกันในรอบเดียว **รวมเป็นข้อความเดียว** (ประหยัดโควตา push)
- **สรุปหลังตลาดปิด:** รอบเช็กสุดท้ายคือ 13:30 น. นิวยอร์ก ตอนคำนวณแนวรับใหม่ช่วงเย็น ระบบจึงเอาระดับเดิมมาเทียบกับราคาต่ำสุดและราคาปิดทั้งวันก่อนเปลี่ยนเป็นระดับใหม่ ([`src/lib/alerts/lateCheck.ts`](src/lib/alerts/lateCheck.ts)) ถ้าราคาแตะหลังรอบเช็กและยังไม่ได้แจ้ง จะส่ง "แตะ … หลังรอบเช็ก" ถ้าราคาปิดต่ำกว่าแนวรับ (หรือต่ำกว่าขอบล่างของโซน) จะส่ง "หลุด …" พร้อมบอกระดับใหม่ที่ใช้แทน แทนที่จะเปลี่ยนเงียบ ๆ ใช้ข้อมูลที่ดึงมาอยู่แล้ว ไม่เปลืองโควตา API เพิ่ม และส่งเฉพาะระดับใน `ALERT_TIERS`
- **หุ้นแตก split:** ถ้าราคาปิดวันก่อนจากผู้ให้ข้อมูลต่างจากราคาปิดที่ใช้คำนวณแนวรับเกิน 20% (เช่น split 10:1) ระบบข้ามหุ้นตัวนั้นทั้งรอบเช็กและสรุปหลังตลาดปิด แทนที่จะแจ้งว่า "ราคาหลุดทุกแนวรับ −90%" แล้วรอบคำนวณเย็นนั้นจะสร้างแนวรับใหม่บนราคาหลัง split
- ป้องกัน job ซ้อนกันด้วยการ "claim" แบบ atomic ใน DB (ไม่ยิงซ้ำแม้ cron รันทับกัน) และถ้า push ล้มเหลวจะคืนสถานะให้รอบถัดไปลองใหม่

NVDA แตะ "แนวรับสำคัญ"

• แนวรับ: $158.50 (MA200)

### Backtest: แนวรับเหล่านี้ช่วยอะไรได้จริงไหม
`npm run backtest` เดินย้อนหลังทีละวัน (5.5 ปี, หุ้นที่ track) ด้วย**โค้ดตัวจริงของระบบ** แล้วเทียบผลหลังแตะแนวรับกับวันอื่น ๆ ของหุ้นตัวเดียวกัน (ปีเดียวกัน ที่เพิ่งลงใกล้เคียงกัน) — วิธีและข้อจำกัดเต็ม ๆ อยู่ที่ [`docs/backtest-report.md`](docs/backtest-report.md)
```bash
set -a; source .env.local; set +a
npm run backtest              # ใช้แคชข้อมูลราคาถ้ามี (ครั้งแรกใช้ ~1 credit ต่อหุ้น)
npm run backtest -- --refresh # ดาวน์โหลดราคาใหม่
```
รันบน GitHub ได้ที่ workflow **Deploy steps** (ติ๊กเฉพาะ backtest) — รายงานเต็มอยู่ในหน้าสรุปของรอบนั้นและไฟล์แนบ

**สรุปจากการรันวันที่ 2026-09-30 (แนวรับเชิงโครงสร้าง, หุ้น 11 ตัว, 2,468 ครั้งที่แตะ, ธ.ค. 2021 – ก.ย. 2026):**
- **ยังไม่มีหลักฐานว่าการซื้อตอนแตะแนวรับดีกว่าซื้อวันอื่น** เมื่อเทียบกับวันของหุ้นตัวเดียวกันในปีเดียวกันที่เพิ่งลงมาใกล้เคียงกัน: รวมทุกระดับ −0.5% (ช่วงเชื่อมั่น 90% −0.9% ถึง 0.0%), แนวรับแรก −0.3%, แนวรับถัดไป −1.2% (แย่กว่าเล็กน้อย)
- **แนวรับสำคัญ** (ระดับเดียวที่แจ้งเตือน): +2.0% แต่ช่วงเชื่อมั่นกว้างมาก (−2.1% ถึง +6.7%) เพราะมีแค่ 58 ครั้งใน ~5 ปี — **สรุปไม่ได้** ทั้งดีหรือไม่ดี
- ตาราง "รับได้/หลุด" เทียบระดับมั่วระยะเท่ากัน: ทุกกลุ่มต่างกันไม่เกินระดับที่เกิดจากความบังเอิญ (แนวรับสำคัญ +6 จุด จาก 60 ครั้ง, Swing Low ที่เด้ง ≥2 ครั้ง +1.7, Fibonacci +2.4, MA50 −3.9)
- เทียบกับเวอร์ชันเก่า (Pivot): ผลแทบเหมือนกัน คือไม่มี edge ทั้งคู่ แต่แจ้งเตือนน้อยลงมาก ≈ 1 ข้อความต่อเดือนต่อผู้รับ (เดิม ~19)
- ดังนั้นควรมองแจ้งเตือนเป็น **"ราคามาถึงระดับที่น่าสนใจแล้ว ลองดูอีกที"** ไม่ใช่สัญญาณซื้อ

ทั้งหมดนี้ไม่ใช่คำแนะนำการลงทุน ผลในอดีตไม่รับประกันอนาคต และมี survivorship bias (หุ้นที่ track คือตัวที่โตมาแล้ว)

### วิเคราะห์ด้วย AI (แท็บ "วิเคราะห์ด้วย AI")
กดปุ่มเดียว ระบบส่งหุ้นทุกตัวที่ track ไปให้ AI จัดอันดับ **ตัวที่ควรดูต่อสูงสุด 5 ตัว** ตามเป้าหมายที่เลือก (เติบโต · ปันผล · ราคาไม่แพง · ความเสี่ยงต่ำ · จังหวะใกล้แนวรับ เลือกได้หลายข้อ ไม่เลือกคือดูภาพรวมสมดุล) — [`src/lib/jobs/analysis.ts`](src/lib/jobs/analysis.ts)

- **AI เห็นอะไร:** เฉพาะตัวเลขของหุ้นที่ track: ราคาปัจจุบัน (ราคาสดที่หน้าเว็บใช้) · P/E · รายได้โต · อัตรากำไร · ปันผล · Beta · ห่างจุดสูงสุด 52 สัปดาห์ · ลงลึกสุดในอดีต · วันประกาศงบ · แนวรับแต่ละระดับพร้อมระยะห่างและสถิติรับได้/หลุด ไม่ส่ง secret ข้อมูลผู้ใช้ หรือข้อความที่พิมพ์เอง (เป้าหมายเลือกจากรายการตายตัว)
- **คำสั่งที่จำกัดบทบาท:** ให้ใช้เฉพาะข้อมูลที่ส่งไป ห้ามแต่งตัวเลข/ข่าว ห้ามทำนายราคา และบอกว่า backtest ของเรายังไม่พบว่าแนวรับให้ผลดีกว่าวันสุ่ม จึงห้ามเสนอแนวรับเป็นสัญญาณซื้อ — ผลลัพธ์คือ "ตัวไหนเข้าเป้าหมายที่สุดตามตัวเลข" ไม่ใช่คำแนะนำซื้อ
- **ตรวจคำตอบก่อนแสดง:** เก็บเฉพาะหุ้นที่อยู่ในรายการเรา (ไม่ซ้ำ ไม่เกิน 5) ตัดข้อความที่ยาวเกิน และราคาที่แสดงมาจากระบบเราเอง ไม่ใช่จาก AI
- **คุมค่าใช้จ่าย:** จำกัดจำนวนครั้งต่อวัน (นิวยอร์ก) ด้วย `AI_DAILY_LIMIT` (ค่าเริ่มต้น 10) **นับเฉพาะครั้งที่ได้ผลลัพธ์** ครั้งที่จบด้วย error ทุกแบบ (key/โมเดลผิด, โควตาหมด, ผู้ให้บริการขัดข้อง, หมดเวลา, อ่านคำตอบไม่ได้) ไม่ถูกนับ — ระบบจองสิทธิ์ไว้ก่อนเรียก (กดพร้อมกันหลายครั้งก็ไม่เกินเพดาน) แล้วคืนให้เมื่อ error · โควตาของผู้ให้บริการเองยังอาจถูกใช้ในบางกรณี (เช่นหมดเวลา) ดูได้ที่หน้า Usage ของผู้ให้บริการ
- **หลายโมเดล + สลับอัตโนมัติ:** ใส่ `AI_MODEL` ได้หลายตัวคั่นด้วยจุลภาค เช่น `gemini-3.8-flash,gemini-3.5-flash-lite` ตัวแรกคือโมเดลหลัก ถ้าใช้ไม่ได้ (โควตารายวันหมด 429, โมเดลถูกยกเลิก 404/400, ตอบว่างเปล่า) ระบบสลับไปตัวถัดไปเอง ถ้าเซิร์ฟเวอร์ขัดข้อง/คนใช้เยอะ (5xx) ลองซ้ำโมเดลเดิม 1 ครั้งหลังรอ 2 วินาทีก่อนสลับ ทั้งหมดใช้งบเวลาเดียวกัน (`AI_TIMEOUT_SECONDS`) และถ้า key ผิด (401/403) หยุดทันที เพราะทุกโมเดลจะล้มแบบเดียวกัน ผลลัพธ์จะบอกว่าใช้โมเดลไหนและตัวไหนถูกข้ามเพราะอะไร · ถ้ามีมากกว่า 1 โมเดล หน้าเว็บมีช่องเลือกโมเดล (เลือกได้เฉพาะที่อยู่ใน `AI_MODEL`) · Google แยกโควตาตามโมเดล การมีตัวสำรองจึงช่วยเมื่อตัวหลักหมดโควตาของวัน
- ผลล่าสุดเก็บไว้ในตาราง `ai_analyses` เปิดหน้าใหม่ก็ยังเห็น
- **ปุ่ม "คัดลอกไปถาม AI เอง":** คัดลอกคำสั่งชุดเดียวกัน (ขอคำตอบเป็นภาษาไทยอ่านง่ายแทน JSON) พร้อมข้อมูลหุ้นและราคาปัจจุบัน ไปวางในแชท AI ที่ใช้อยู่ (Gemini, ChatGPT, Claude ฯลฯ) ไม่เรียก AI จากระบบ ไม่ใช้โควตา และใช้ได้แม้ยังไม่ได้ตั้งค่า AI — ทางออกเมื่อโควตาหมดหรือผู้ให้บริการล่ม

**ตั้งค่า** (Vercel → Settings → Environment Variables, Production แล้ว Redeploy) — ใช้ผู้ให้บริการใดก็ได้ที่รองรับรูปแบบ OpenAI `…/chat/completions`:

| ตัวแปร | ชนิด | ค่า |
|---|---|---|
| `AI_API_KEY` | **Secret** | key จากผู้ให้บริการ |
| `AI_MODEL` | Config | ชื่อโมเดล หรือหลายชื่อคั่นด้วยจุลภาค (ตัวแรก = หลัก ที่เหลือ = สำรอง) |
| `AI_BASE_URL` | Config (ไม่บังคับ) | ค่าเริ่มต้น `https://openrouter.ai/api/v1` |

ตัวอย่างค่า (ชื่อโมเดล/โควตาฟรีเปลี่ยนบ่อย ตรวจที่หน้าของผู้ให้บริการก่อน):

| ผู้ให้บริการ | `AI_BASE_URL` | `AI_MODEL` (ตัวอย่าง) |
|---|---|---|
| OpenRouter (รวมหลายโมเดล มีตัวฟรี) | `https://openrouter.ai/api/v1` | ชื่อจากหน้า Models เช่น `…:free` |
| Google Gemini (AI Studio) | `https://generativelanguage.googleapis.com/v1beta/openai` | เช่น `gemini-3.8-flash`, `gemini-3.5-flash-lite` (รุ่น 2.5 ปิดรับผู้ใช้ใหม่แล้ว) |
| Groq | `https://api.groq.com/openai/v1` | โมเดล Llama ที่ Groq เปิดให้ |
| OpenAI | `https://api.openai.com/v1` | ตามบัญชี |

ไม่บังคับ: `AI_DAILY_LIMIT` (ครั้ง/วัน) · `AI_TIMEOUT_SECONDS` (ค่าเริ่มต้นและสูงสุด 280 = เวลารวมของทุกโมเดลและการลองซ้ำ; ฟังก์ชันนี้ตั้งให้รันได้ 300 วินาทีตามเพดานของ Vercel แบบ Fluid compute โดยเผื่อเวลาดึงราคาและฐานข้อมูล — ตั้งน้อยกว่านี้ได้ถ้าไม่อยากรอนาน) · `AI_TEMPERATURE` (ส่งไปเฉพาะเมื่อตั้ง บางโมเดลไม่รับค่าอื่นนอกจากค่าเริ่มต้นของมัน)

> ⚠️ ข้อมูลหุ้นที่ติดตามจะถูกส่งไปผู้ให้บริการ AI — แพ็กเกจฟรีของบางเจ้าอาจนำข้อมูลไปปรับปรุงโมเดลได้ ตรวจเงื่อนไขก่อนใช้ (ข้อมูลนี้ไม่มีความลับ แต่บอกว่าคุณสนใจหุ้นอะไร) · โมเดลฟรีมักช้า ถูกจำกัดบ่อย และทำตามรูปแบบ JSON ไม่เสถียร ถ้าเจอ "อ่านคำตอบของ AI ไม่ได้" บ่อย ให้ลองโมเดลอื่น

### เว็บสาธารณะ (portfolio): ใครก็ดูได้ แก้ได้เฉพาะเจ้าของ
- **ผู้เยี่ยมชม (ไม่ได้เข้าสู่ระบบ):** เปิดได้ทุกเมนู เห็นข้อมูลจริงที่อัปเดตทุกวัน แต่ไม่มีปุ่มจัดการหรือช่องกรอกใด ๆ ไม่มีลากเรียงลำดับ รีเฟรชราคา คัดลอก สั่ง AI สรุปข่าว เพิ่ม/ลบหุ้น หรือสวิตช์ผู้รับ กดได้แค่เมนู ปุ่ม "เข้าสู่ระบบ" ปุ่มกาง/หุบรายละเอียด และลิงก์ไปข่าวต้นทาง (เปิดแท็บใหม่) ทุกหน้ามีแถบ "โหมดผู้เยี่ยมชม" และข้อความว่าไม่ใช่คำแนะนำการลงทุน
- **เจ้าของ (เข้าสู่ระบบแล้ว):** ใช้งานได้ครบเหมือนเดิม
- **กันที่ server ไม่ใช่แค่ซ่อนปุ่ม:** [`src/proxy.ts`](src/proxy.ts) ให้ทุกคนใช้ได้แค่ `GET`/`HEAD` คำขอที่แก้ข้อมูล (POST/PUT/PATCH/DELETE) ต้องมีเซสชันเจ้าของ ไม่มีจะได้ `401` · ปุ่มรีเฟรชราคา (`/api/prices?force=1`) ข้าม cache ได้เฉพาะเจ้าของ ผู้เยี่ยมชมใช้ cache ร่วม 5 นาที จึงไม่ทำให้เรียก API ราคาถี่ขึ้น · หน้าแต่ละหน้าเช็กสิทธิ์ด้วย [`src/lib/viewer.ts`](src/lib/viewer.ts)
- **ข้อมูลส่วนตัวผู้รับ LINE ([`src/lib/recipients.ts`](src/lib/recipients.ts)):** สำหรับผู้เยี่ยมชม server ตัด LINE user id (แสดง `U••••••••`) ชื่อจาก LINE และชื่อเรียกออกก่อนส่งไปเบราว์เซอร์ จึงไม่อยู่ใน HTML ด้วย แสดงเป็น "ผู้รับ #1" พร้อม "✓ ดึงชื่อและรูปโปรไฟล์จาก LINE แล้ว" เป็นหลักฐานว่าดึงข้อมูลได้จริง · รูปโปรไฟล์แสดงเฉพาะคนที่เจ้าของเปิดสวิตช์ **"แสดงรูปบนหน้าสาธารณะ"** ในหน้าผู้รับ (ตั้งใจไว้สำหรับบัญชีของเจ้าของเอง ค่าเริ่มต้นปิดทุกคน) คนอื่นเป็นไอคอนเงา
- หน้าวิเคราะห์ AI และหน้าข่าวแสดงผลล่าสุดเท่านั้น ไม่แสดงชื่อ env ที่ยังไม่ได้ตั้ง และจำนวนครั้งที่ใช้วันนี้

**ให้ Google ค้นเจอ (SEO)**
- [`src/app/robots.ts`](src/app/robots.ts) → `/robots.txt` อนุญาตทุกหน้า ยกเว้น `/api/` และ `/login` และชี้ไปที่ sitemap
- [`src/app/sitemap.ts`](src/app/sitemap.ts) → `/sitemap.xml` รายการหน้าสาธารณะทั้ง 6 หน้า (จาก `PUBLIC_PAGES` ใน [`src/lib/site.ts`](src/lib/site.ts))
- [`src/app/layout.tsx`](src/app/layout.tsx) → title/description, Open Graph (ตัวอย่างลิงก์เวลาแชร์), canonical URL · แต่ละหน้ามี `metadata` ของตัวเอง (ชื่อหน้า + คำอธิบาย) · หน้า login ตั้ง `noindex`
- ที่อยู่เว็บ: ใช้ `SITE_URL` ถ้าตั้ง (เช่นเมื่อมีโดเมนของตัวเอง) ไม่อย่างนั้นใช้ `VERCEL_PROJECT_PRODUCTION_URL` ที่ Vercel ให้มาเอง
- **ส่งให้ Google รู้จักเร็วขึ้น:** [Google Search Console](https://search.google.com/search-console) → Add property → URL prefix `https://stock-support-alert.vercel.app` → ยืนยันด้วย **HTML tag** (คัดลอกค่า `content` มาใส่ `verification: { google: "…" }` ใน `metadata` ของ `src/app/layout.tsx` แล้ว deploy) → เมนู Sitemaps ใส่ `sitemap.xml` → Submit

### ข่าวที่กระทบหุ้น (แท็บ "ข่าว")
ระบบเก็บข่าวฟรีทุกชั่วโมง แล้วให้ AI สรุปทุกวันทำการก่อนตลาดเปิด ว่าข่าวกระทบตลาดและหุ้นที่ track แต่ละตัวอย่างไร (หรือกด "สรุปข่าวตอนนี้" เองได้) — [`src/lib/jobs/news.ts`](src/lib/jobs/news.ts)

- **แหล่งข่าว (ฟรี):** Finnhub `company-news` ของหุ้นทุกตัว และ `news?category=general` (ข่าวตลาด ส่วนใหญ่เป็นพาดหัว Reuters) ใช้ `FINNHUB_API_KEY` ตัวเดิม ประมาณ 21 ครั้งต่อรอบ เว้นช่วง 1.2 วินาทีเพื่อไม่ชนเพดาน 60 ครั้ง/นาทีที่ใช้ร่วมกับราคาสด
- **อ่านเนื้อข่าวเต็ม:** เปิดหน้าข่าวต้นทางแล้วดึงเนื้อหาแบบ reader view ของเบราว์เซอร์ (Mozilla Readability) ส่วนใหญ่อ่านได้ (Yahoo Finance, Motley Fool, 24/7 Wall St. ฯลฯ) ส่วนที่มี paywall หรือกันบอต (Seeking Alpha, Benzinga, Reuters ผ่าน Google News, หน้าที่โหลดเนื้อหาด้วย JavaScript อย่าง CNBC) ใช้พาดหัวและเรื่องย่อจาก Finnhub แทน ระบบไม่หลบการบล็อก · ลิงก์ของ Finnhub ถูกเปิดทีละลิงก์ (ตัว redirect ของ Finnhub ปฏิเสธถ้าเปิดพร้อมกันหลายลิงก์) ต่อรอบอ่านไม่เกิน 100 ข่าว อ่านข่าวที่พาดหัวพูดถึงหุ้นเราก่อน
- **เลือกข่าวให้ AI:** จับคู่ทุกข่าวกับหุ้นทุกตัวด้วย ticker และชื่อบริษัท (เช่น NVDA/Nvidia, TSM/TSMC) ข่าวที่ Finnhub จัดไว้ใต้ ticker แต่ไม่ได้พูดถึงหุ้นนั้นจริงถูกตัด ข่าวที่พูดถึงหลายตัวนับให้ทุกตัว **ไม่ตัดบทความความเห็น** ("ควรซื้อไหม" ฯลฯ) แต่ AI ต้องติดป้ายว่าเป็น "ความเห็น" · ไม่เกิน `NEWS_PER_STOCK` ข่าวต่อหุ้น (ค่าเริ่มต้น 6) + ข่าวตลาด 15 ข่าว · เนื้อหารวมไม่เกิน `NEWS_PROMPT_MAX_CHARS` ตัวอักษร (ค่าเริ่มต้น 160,000 ≈ 40k token)
- **ช่วงข่าว:** ตั้งแต่เวลาเดียวกันของวันทำการก่อนหน้า (รอบเช้าวันจันทร์ครอบคลุมเสาร์–อาทิตย์ วันหลังวันหยุดครอบคลุมวันหยุด)
- **AI ตอบอะไร:** ภาพรวมตลาด และแต่ละหุ้น: ทิศทาง (บวก/ลบ/ผสม/กลาง ๆ) · กระทบมากแค่ไหน · สรุป · ประเด็น 1–5 ข้อ แต่ละข้อมีป้าย **ข้อเท็จจริง / ความเห็น / AI ตีความ** (เช่น ข่าว TSMC ที่อาจกระทบ NVDA) และเลขข่าวอ้างอิงที่กดไปอ่านต้นทางได้ · ประเด็นที่ไม่มีแหล่งอ้างอิงถูกจัดเป็น "AI ตีความ" เสมอ · ห้ามเพิ่มข้อมูลที่ไม่อยู่ในข่าว ห้ามทำนายราคา
- **ใช้ AI ตัวเดียวกับแท็บ "วิเคราะห์ด้วย AI"** (`AI_API_KEY`, `AI_MODEL`, สลับโมเดลสำรองเหมือนกัน) จำกัด `NEWS_DAILY_LIMIT` ครั้งต่อวัน (ค่าเริ่มต้น 3 รวมรอบอัตโนมัติ นับเฉพาะครั้งที่สำเร็จ) · prompt ใหญ่ (หลายหมื่น token) เหมาะกับ Gemini/OpenRouter ถ้าใช้ Groq แบบฟรีให้ลด `NEWS_PROMPT_MAX_CHARS`
- **แท็บ "วิเคราะห์ด้วย AI" ได้ข่าวด้วย:** สรุปข่าวรายหุ้นล่าสุด (ถ้าอายุไม่เกิน 36 ชั่วโมง) ถูกส่งไปพร้อมตัวเลข โดยบอก AI ว่าเป็นสรุปจากข่าวฟรีที่อาจไม่ครบ
- **เก็บข้อมูล:** ตาราง `news_articles` (เนื้อข่าวเต็มเก็บแค่ 7 วันเพื่อใช้สรุป แถวทั้งหมดลบเมื่อครบ 30 วัน) และ `news_briefs` (สรุปที่ได้ เก็บเฉพาะพาดหัว แหล่ง และลิงก์ ไม่เก็บเนื้อข่าว)
- **ข้อจำกัด:** ข่าวฟรีมาช้ากว่าแหล่งแบบเสียเงินเป็นนาทีถึงชั่วโมง และราคามักตอบสนองไปแล้วบางส่วนก่อนตลาดเปิด AI อาจตีความผิดหรือตกหล่น ตรวจกับข่าวต้นทางทุกครั้ง ไม่ใช่คำแนะนำการลงทุน
- รันเองจากเครื่อง: `set -a; source .env.local; set +a; npm run news` (เก็บข่าว) · `npm run news -- brief` (เก็บข่าว + สรุป ใช้ AI 1 ครั้ง)

| อัตรากำไรสุทธิ | ขายได้ $100 เหลือกำไรเท่าไร | Finnhub |
| ผลตอบแทนปันผล | ถือหุ้นมูลค่า $100 ได้ปันผลกี่ดอลลาร์ต่อปี (ไม่แสดงถ้าไม่มีตัวเลข = ไม่จ่ายหรือไม่ทราบ) | Finnhub |
| Beta | ถ้าตลาดลง 10% หุ้นนี้ลงโดยเฉลี่ยกี่ % | Finnhub |
| เทียบจุดสูงสุด 52 สัปดาห์ | ราคาอยู่ตรงไหนของรอบปี (ใช้ราคาบนการ์ด) | ราคาย้อนหลัง |
| ลงลึกสุดในอดีต | ช่วง ~5 ปี เคยร่วงจากจุดสูงสุดกี่ % เมื่อไหร่ ถ้าซื้อที่จุดสูงสุดเงิน $100 จะเหลือเท่าไร และกลับมาได้หรือยัง | ราคาย้อนหลัง |
| ประกาศงบครั้งถัดไป | อีกกี่วัน (ภายใน 7 วันจะเตือนสีเหลือง เพราะราคามักแกว่งแรง) | Finnhub |
| คำแนะนำนักวิเคราะห์ | กี่คนแนะนำ ซื้อ/ถือ/ขาย (เดือนล่าสุด) — บอกด้วยว่าคำแนะนำ "ซื้อ" เป็นเรื่องปกติของโบรกเกอร์ จึงไม่ใช่สัญญาณแรง; เตือนเมื่อมีคนแนะนำขายมากผิดปกติ | Finnhub (ฟรี) |
| ราคาเป้าหมายนักวิเคราะห์ | ค่าเฉลี่ยเป้า 12 เดือน (ต่ำสุด–สูงสุด) เทียบราคาตอนนี้ — ราคาเป้าหมายมักมองบวกเกินจริง | Finnhub (อาจต้องแพ็กเกจจ่ายเงิน ถ้าไม่ได้จะไม่แสดง) |

- จุดสีเหลือง = ตัวเลขที่หมายถึงความเสี่ยงสูงขึ้น หรือมีเหตุการณ์ใกล้เข้ามา (ไม่ได้แปลว่าดี/ไม่ดี)
- **ไม่ทำให้หน้าเว็บช้า:** งานคำนวณแนวรับรายวันดึงราคาย้อนหลัง ~5 ปี (credit เท่าเดิม เพราะ Twelve Data คิดต่อหุ้นต่อคำขอ) และข้อมูลพื้นฐานจาก Finnhub วันละครั้ง เก็บลงตาราง `stock_profiles` หน้าเว็บอ่านจากฐานข้อมูลอย่างเดียว; หุ้นที่เพิ่มใหม่ได้ข้อมูลทันทีตอนเพิ่ม
- แนวรับยังคำนวณจาก ~1 ปีล่าสุดเหมือนเดิม (ตรวจแล้วว่าค่าไม่เปลี่ยน)
- หุ้นเล็ก/ต่างประเทศบางตัว Finnhub ไม่มีข้อมูลพื้นฐาน จะแสดงเฉพาะตัวที่มี
- ข้อมูลนักวิเคราะห์ (ความเห็น ไม่ใช่การทำนายของระบบ) ดึงทุก 3 วัน เพื่อให้รอบรายวันใช้ Finnhub ไม่เกิน 60 ครั้ง/นาที; AI ในแท็บวิเคราะห์ก็ได้รับข้อมูลนี้ พร้อมคำสั่งให้ถือเป็นความเห็นที่มักมองบวก
- เติมทันทีโดยไม่รองานรายวัน: `set -a; source .env.local; set +a; npm run refresh:profiles`

### โลโก้หุ้น
ดึง **ครั้งเดียวตอนเพิ่มหุ้น** แล้วเก็บ **ตัวไฟล์รูปไว้ในฐานข้อมูลของเรา** (คอลัมน์ `symbols.logo_*`) หน้าเว็บแสดงผ่าน `/api/logo/<symbol>` ของเราเอง จึงไม่ต่อเว็บอื่นตอนใช้งาน (ทั้งหน้าแนวรับและหน้าจัดการหุ้น) และไม่ขึ้นกับว่า Finnhub ตอบหรือไม่
- **ลำดับแหล่ง:** Financial Modeling Prep (ไม่ต้องใช้ key) → Finnhub (`FINNHUB_API_KEY`) → Twelve Data (`STOCK_API_KEY`) → ถ้าไม่มีเลยแสดงตัวอักษรย่อของ ticker
- **ความปลอดภัยของรูป:** รับเฉพาะ PNG/JPEG/GIF/WebP (ตรวจจากไบต์จริง ไม่เชื่อ Content-Type; ไม่รับ SVG) ขนาด 200B–150KB และตาม URL เฉพาะโดเมนของผู้ให้บริการ เสิร์ฟด้วย header กันการรันสคริปต์ และอยู่หลังหน้า login
- **ตัวที่ยังไม่มีโลโก้:** งานคำนวณแนวรับรายวันจะเติมให้รอบละไม่เกิน 3 ตัว (ตัวที่หาไม่เจอจะลองใหม่ทุก 7 วัน ไม่ยิงซ้ำรัว ๆ)
- **หุ้นที่เพิ่มไว้ก่อนมีฟีเจอร์นี้ / ดึงใหม่:**
  ```bash
  set -a; source .env.local; set +a
  npm run seed:logos              # เติมตัวที่ยังไม่มี (ข้ามตัวที่ลองไปไม่เกิน 7 วัน)
  npm run seed:logos -- --retry   # ลองตัวที่ยังไม่มีอีกครั้งทันที
  ```
- โลโก้แสดงบนพื้นสีอ่อนเพราะหลายอันสีเข้มหรือโปร่งใส — [`src/lib/stock/logo.ts`](src/lib/stock/logo.ts), [`src/lib/jobs/logos.ts`](src/lib/jobs/logos.ts)

### ผู้รับแจ้งเตือน (หน้า "ผู้รับแจ้งเตือน")
- ใครแอด LINE OA เป็นเพื่อน ระบบเก็บเป็นเพื่อนอัตโนมัติ (แสดงชื่อและรูปจาก LINE) แต่ **ยังไม่ส่ง push ให้** จนกว่าจะเปิดสวิตช์ "รับแจ้งเตือน" ในหน้านี้
- เปิดรับได้พร้อมกันไม่เกิน `MAX_PUSH_RECIPIENTS` คน (ค่าเริ่มต้น 5) เพราะโควตาของ LINE นับ "ต่อผู้รับ" — ระบบตรวจเพดานฝั่งเซิร์ฟเวอร์ ไม่ให้เกินแม้กดพร้อมกัน
- **เมื่อเปิดสวิตช์ (ปิด → เปิด)** ระบบส่งข้อความ LINE แจ้งผู้รับว่าจะได้รับการแจ้งเตือนเมื่อหุ้นที่ติดตามเข้าแนวรับ — นับโควตา push 1 ข้อความต่อครั้ง จึงส่งไม่เกิน 1 ครั้งต่อคนต่อ 24 ชั่วโมง (กดปิด-เปิดรัว ๆ ไม่เผาโควตา) และถ้าส่งไม่สำเร็จ (เช่นโควตาเต็ม) การเปิดรับยังสำเร็จอยู่ หน้าเว็บจะแจ้งผลการส่ง
- เพื่อนทุกคน (แม้ไม่ได้เปิดรับ push) พิมพ์ `ขอแนวรับ` ถามได้ ซึ่งตอบด้วย reply message ที่ไม่นับโควตา push
- ถ้าเพื่อนบล็อก/ลบ OA จะถูกปิดรับแจ้งเตือนอัตโนมัติ และต้องเปิดใหม่เองหลังแอดกลับ
- **LINE ไม่เปิดเผย LINE ID** ให้ระบบ ได้แค่ชื่อที่ตั้งใน LINE กับรูปโปรไฟล์ จึงมีช่อง "ชื่อเรียก" ให้พิมพ์เองเพื่อจำง่าย
- ตัวแปร `LINE_ALLOWED_USER_IDS` ที่เคยใช้ **เลิกใช้แล้ว** (ลบออกจาก Vercel ได้ ปล่อยไว้ก็ไม่มีผล)

### ราคาสดบนหน้าเว็บ (แยกจาก flow แจ้งเตือน)
หน้า **แนวรับปัจจุบัน** ดึงราคาสดมาแสดงเมื่อเปิดหน้า และมีปุ่ม "รีเฟรชราคา" — ใช้ **Finnhub** (ตั้ง `FINNHUB_API_KEY`) → ถ้าไม่ได้ตั้ง key หรือดึงไม่ได้จะลอง **Yahoo** (ไม่เป็นทางการ อาจถูกบล็อก) → ถ้ายังไม่ได้จะใช้ราคาที่เก็บไว้ตอนรอบเช็ค Twelve Data
- **เพื่อแสดงผลเท่านั้น** ไม่เขียนลงฐานข้อมูล ไม่ใช้ credit ของ Twelve Data และไม่เปลี่ยนตัวเลขที่ใช้แจ้งเตือน (แจ้งเตือน/แนวรับยังมาจาก Twelve Data ตามเดิม)
- ใต้ราคาแต่ละตัวบอกเวลาและแหล่งที่มา (Finnhub / Yahoo / รอบเช็กล่าสุด) ตลาดปิดจะเป็นราคาปิดล่าสุด
- **แคชร่วมในฐานข้อมูล (ตาราง `live_quotes`) 5 นาที** ใช้ร่วมกันทุกคนและทุกเซิร์ฟเวอร์ — โหลดหน้ารัว ๆ หรือหลายคนใช้พร้อมกัน ก็ยิง Finnhub/Yahoo ไม่เกิน 1 ครั้งต่อหุ้นต่อ 5 นาที (หุ้น 20 ตัว ≈ 4 ครั้ง/นาที เทียบเพดานฟรี 60 ครั้ง/นาที) ปรับได้ด้วย `LIVE_PRICE_TTL_SECONDS`
- ปุ่ม "รีเฟรชราคา" ข้ามแคชได้ แต่ไม่ดึงซ้ำหุ้นตัวเดิมภายใน 30 วินาที (`LIVE_PRICE_MIN_REFRESH_SECONDS`) และคำขอที่ซ้อนกันในเซิร์ฟเวอร์เดียวกันใช้การดึงเดียวกัน
- **เพดานเวลา:** แต่ละแหล่งรอไม่เกิน 4 วินาทีแล้วข้ามไปแหล่งถัดไป ทั้งคำขอรวมไม่เกิน 12 วินาที (`LIVE_PRICE_DEADLINE_MS`) ตัวที่ไม่ทันจะใช้ราคาเก่าล่าสุดของ live (ติดป้าย "ค่าเก่า") แล้วค่อยใช้ราคาจากรอบเช็ก Twelve Data
- ดึงเฉพาะหุ้นที่ track อยู่ — [`src/lib/stock/live.ts`](src/lib/stock/live.ts), [`src/lib/jobs/livePrices.ts`](src/lib/jobs/livePrices.ts), [`/api/prices`](src/app/api/prices/route.ts)

### เกณฑ์ความเร็ว: ทุกหน้า/API ต้องตอบไม่เกิน 15 วินาที
- **Production:** การโหลดข้อมูลของหน้าเว็บมีเพดาน 12 วินาที (และต่อฐานข้อมูลรอไม่เกิน 10 วินาที) เกินแล้วจะขึ้นหน้า "โหลดข้อมูลไม่สำเร็จ" พร้อมปุ่มลองใหม่ ไม่ปล่อยให้ค้าง ส่วนแหล่งราคาภายนอกที่ช้าจะถูกข้ามไปแหล่งถัดไปตามข้างบน
- **ตอนทดสอบ:** ตรวจได้ด้วยสคริปต์ที่ถือว่าคำขอที่ช้ากว่า 15 วินาที หรือไม่ตอบ 200 คือ **ตก** (exit code 1):
  ```bash
  SMOKE_USERNAME=<ชื่อผู้ใช้> SMOKE_PASSWORD=<รหัส> npm run smoke -- https://<โดเมน-vercel>
  ```
  ทดสอบโหลดทุกหน้า/API พร้อมกัน 18 คำขอ × 3 รอบ (แบบเดียวกับที่เบราว์เซอร์โหลดเมนูล่วงหน้า) — เป็นการอ่านอย่างเดียว

### ลำดับการแสดงหุ้น
หน้า **แนวรับปัจจุบัน**: กดค้างที่ปุ่มจุด 6 จุดมุมการ์ดแล้วลากเพื่อจัดลำดับ (ใช้ได้ทั้งเมาส์ ทัชสกรีน และคีย์บอร์ด: Space หยิบ → ลูกศรย้าย → Space วาง)

### โหมดเช็ควันละครั้ง (ค่าเริ่มต้นของ workflow)
เพื่อประหยัดโควตา workflow เรียก `/api/cron/check?mode=daily` **วันละ 2 รอบ: 10:30 น. นิวยอร์ก (1 ชม. หลังเปิด = 21:30 น. ไทยช่วง EDT / 22:30 น. ช่วง EST) และ 13:30 น. นิวยอร์ก (00:30 / 01:30 น. ไทย)** รอบแรกให้ทันดูก่อนนอนและจับช่วงเปิดตลาดที่แกว่งแรงที่สุด ระดับที่แจ้งไปแล้วจะไม่แจ้งซ้ำในรอบที่สองจนกว่าราคาจะเด้งขึ้นก่อน
เหลือเวลาตัดสินใจซื้อทัน โหมดนี้ต่างจากโหมดถี่ตรงที่ **นับ "ราคาต่ำสุดของวัน" เป็นการแตะด้วย** (ไม่งั้นถ้าแตะตอนเช้าแล้วเด้งกลับจะพลาด) และข้อความแจ้งเตือนจะมีบรรทัด "ต่ำสุดวันนี้"
- วัน early close (ปิด 13:00 น. นิวยอร์ก เช่นวันหลัง Thanksgiving) จะไม่มีรอบเช็ค เพราะ 13:30 เลยเวลาปิดไปแล้ว
- ราคาต่ำสุดที่นับคือของช่วงเปิดตลาดจนถึงเวลาเช็ค ถ้าแตะแนวรับหลังจากนั้น จะถูกแจ้งใน "สรุปหลังตลาดปิด" ตอนเย็น
- **รับรอบที่มาช้าได้:** GitHub cron มักดีเลย์ 15–60 นาที แต่ละรอบจึงรับได้ตั้งแต่เวลาของมันจนถึงรอบถัดไป (รอบสุดท้ายถึงตลาดปิด) รอบที่ทำงานครบจะบันทึกไว้ในตาราง `job_runs` (แยกต่อรอบ) cron อีกตัวของรอบเดียวกัน (ที่ตั้งไว้เผื่อ EDT/EST) จึงข้ามเอง (ถ้าดึงราคาไม่ครบ จะไม่บันทึก และลองใหม่ได้ โดยไม่ส่งแจ้งเตือนซ้ำ)
- อยากกลับไปเช็คทุก 30 นาที: ใช้ cron `*/30 13-20 * * 1-5` + `0 21 * * 1-5` และเรียก `/api/cron/check` (ไม่ใส่ `mode`) — endpoint รองรับทั้งสองโหมด
- Supabase Free จะ pause project ถ้าไม่มี activity ~7 วัน การรันวันละครั้งวันทำการยังนับเป็น activity แต่หยุดยาวหลายวันควรระวัง

### ตลาดเปิด/ปิด (DST)
GitHub cron เป็น UTC และไม่รู้จัก DST จึงตั้งให้ครอบคลุมทั้งเวลา EDT/EST แล้วให้ endpoint ตัดสินเองด้วย
`America/New_York` ผ่าน `Intl` (ไม่ hardcode offset) รวมวันหยุด NYSE (Good Friday, Juneteenth ฯลฯ) และวัน early close 13:00
— [`src/lib/market/calendar.ts`](src/lib/market/calendar.ts)

### Stock API → **Twelve Data (free)**
| ตัวเลือก | ราคา real-time | OHLC ย้อนหลัง | ข้อสรุป |
|---|---|---|---|
| **Twelve Data** | ✅ `/quote` | ✅ `/time_series` 1day ได้ถึง 5,000 แท่ง | **เลือก** — ฟรี 800 credit/วัน, 8/นาที, batch หลาย symbol ในคำขอเดียว, ใช้ API key |
| Finnhub | ✅ ฟรี | ❌ candle ย้อนหลังเป็น premium | ใช้คำนวณแนวรับไม่ได้ |
| Alpha Vantage | ✅ | ⚠️ ฟรีแค่ 25 คำขอ/วัน และ full history เป็น premium | ไม่พอสำหรับ MA200 + เช็คทุก 30 นาที |
| Yahoo (unofficial) | ✅ | ✅ | ไม่มี SLA, มักบล็อก IP ของ Vercel/GitHub, ไม่มี key |

**ออกแบบให้ประหยัด rate limit**
- พอร์ต 5 ตัว = `/quote` 1 คำขอ (5 credits) ต่อรอบ — โหมดวันละครั้ง ≈ 5 credits/วัน (โหมดทุก 30 นาที ≈ 70/วัน) จาก 800
- ราคาที่ query แล้ว cache ในตาราง `quotes` (TTL 5 นาที) — รันซ้ำ/กดเรียกมือไม่ยิง API ซ้ำ
- แนวรับ cache ในตาราง `support_levels` และคำนวณใหม่วันละครั้ง (ข้ามถ้าข้อมูลของ session ล่าสุดมีอยู่แล้ว)
- หน้าเว็บอ่านจาก cache ล้วน ๆ ไม่เรียก API
- **รองรับ 20 ตัว** (`MAX_TRACKED_SYMBOLS`, ค่าเริ่มต้น 20) ภายใต้ limit 8 credits/นาที โดยแต่ละงานดึงครั้งละไม่เกิน 8 ตัว (`API_CREDITS_PER_MINUTE`)
  แล้ว **workflow วนเรียกซ้ำโดยเว้น 61 วินาที** จนครบ — 20 ตัว = 3 ชุด ใช้เวลาเพิ่มราว 2 นาทีต่อรอบ (ทำเป็นหลายการเรียกสั้น ๆ เพื่อไม่ชนเพดาน 60 วินาทีของ Vercel ฟรี)
  - เช็คราคา: `/api/cron/quotes` อุ่น cache ทีละชุด แล้ว `/api/cron/check` อ่านจาก cache ทั้งหมด (ไม่เรียก API)
  - คำนวณแนวรับ: `/api/cron/recalculate` ทำทีละชุดและตอบ `remaining` กลับมา
  - ถ้าบางชุดล้มเหลว ตัวที่ยังไม่ได้ราคาจะถูกข้ามในรอบนั้น (ไม่ทำให้ทั้งรอบพัง)
  - เพิ่มหุ้นผ่านหน้าเว็บรัว ๆ เกิน 8 ตัวใน 1 นาทีจะชน limit (ขึ้น error) — เว้นสักนาทีแล้วเพิ่มต่อ
- ข้อความ LINE ที่ยาวเกิน 4,500 ตัวอักษรจะแบ่งเป็นหลายข้อความอัตโนมัติ (สูงสุด 5 ข้อความ/ครั้ง)
- เปลี่ยน provider ได้โดย implement interface `StockDataProvider` ([`src/lib/stock/types.ts`](src/lib/stock/types.ts))

> เช็ค limit ล่าสุดของ free plan ที่ https://twelvedata.com/pricing

## Setup

### 0. เตรียมเครื่อง
```bash
git clone https://github.com/extratha/stock-support-alert.git
cd stock-support-alert
npm install
cp .env.example .env.local
```

### 1. Twelve Data API key
สมัครฟรีที่ https://twelvedata.com → Dashboard → API Keys → ใส่ใน `STOCK_API_KEY`

### 2. Database (Supabase)
1. https://supabase.com → New project (free)
2. **Project Settings → Database → Connection string** เลือกแบบ **Transaction pooler** (พอร์ต 6543) → ใส่ใน `DATABASE_URL`
   (ถ้ามี `?sslmode=require` ก็ใส่ต่อท้าย)
3. สร้างตาราง:
   ```bash
   npm run db:migrate   # อ่าน DATABASE_URL จาก environment
   ```
   หรือ `set -a; source .env.local; set +a; npm run db:migrate`
   หลังจากนั้น **Vercel รัน migrate ให้เองทุกครั้งที่ deploy production** (script `vercel-build` = `db:migrate` แล้ว `next build`) ใช้ `DATABASE_URL` จาก env ของ Vercel — schema เป็นแบบรันซ้ำได้ (เพิ่มเฉพาะที่ยังไม่มี) ถ้าต่อฐานข้อมูลไม่ได้ build จะล้มและเวอร์ชันเดิมยังออนไลน์อยู่ · preview deployment ไม่แตะฐานข้อมูล
   เมื่อวิธีคำนวณแนวรับเปลี่ยน (`SUPPORT_LOGIC_VERSION`) รอบคำนวณถัดไปจะคำนวณใหม่ทุกตัวเอง ไม่ต้องรอวันทำการใหม่

### 3. LINE Official Account
1. https://developers.line.biz/console/ → สร้าง **Provider** → สร้าง channel ชนิด **Messaging API** (จะสร้าง OA ให้อัตโนมัติ)
2. แท็บ **Basic settings** → คัดลอก **Channel secret** → `LINE_CHANNEL_SECRET`
3. แท็บ **Messaging API** → กด Issue **Channel access token (long-lived)** → `LINE_CHANNEL_ACCESS_TOKEN`
4. ในแท็บเดียวกัน **Webhook URL** = `https://<โดเมน-vercel-ของคุณ>/api/line/webhook` → Verify → เปิด **Use webhook**
   (ทำหลัง deploy ข้อ 5)
5. ใน LINE Official Account Manager ปิด **Auto-reply messages** และ **Greeting message** (ให้ระบบเราตอบเอง)
6. สแกน QR ในแท็บ Messaging API เพื่อเพิ่มเพื่อน → ระบบจะเก็บ `userId` ของคุณอัตโนมัติ (event `follow`)

> ⚠️ **โควตา push:** แผน Free ของ LINE OA ส่งได้จำกัด (ประมาณ 200 ข้อความ/เดือน ดูแผนล่าสุดในประเทศคุณ) ระบบจึงรวมหลายแจ้งเตือนในรอบเดียวเป็นข้อความเดียว

### 4. Secrets ของระบบ
```bash
openssl rand -hex 32   # รันสองครั้ง: ผลแรกเป็น CRON_SECRET ผลที่สองเป็น SESSION_SECRET
```
- `ADMIN_USERNAME` (ไม่ตั้ง = `admin`) และ `ADMIN_PASSWORD` (รหัสผ่านที่ยาวพอ) ใช้เข้าหน้าเว็บผ่านหน้า login
- `SESSION_SECRET` ใช้เซ็น cookie เซสชัน (ยาวอย่างน้อย 16 ตัวอักษร) — ถ้าไม่ตั้งบน production เว็บจะตอบ 503 (ไม่เปิดโล่ง)

**การ login:** เซสชันเป็น cookie ที่เซ็นลายเซ็น (HttpOnly, Secure, SameSite=Lax) อายุ 7 วัน ไม่เก็บอะไรใน DB กดปุ่ม "ออกจากระบบ" เพื่อล้าง cookie
เปลี่ยน `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `SESSION_SECRET` อย่างใดอย่างหนึ่งแล้ว Redeploy = ทุกเครื่องถูกบังคับ login ใหม่
ข้อจำกัด: ไม่มีระบบล็อกเมื่อเดารหัสผิดหลายครั้ง (มีแค่หน่วง 0.5 วินาทีต่อครั้งที่ผิด) จึงควรตั้งรหัสให้ยาวและเดายาก
`/api/cron/*` (bearer `CRON_SECRET`) และ `/api/line/webhook` (ลายเซ็น LINE) ไม่ผ่านหน้า login

### 5. Deploy บน Vercel (free)
1. https://vercel.com/new → Import repo `extratha/stock-support-alert`
2. **Environment Variables**: ใส่ครบทุกตัวใน [ตารางด้านล่าง](#environment-variables)
3. Deploy → จดโดเมน เช่น `https://stock-support-alert.vercel.app`
4. กลับไปตั้ง LINE Webhook URL (ข้อ 3.4)
5. เปิดเว็บ → **จัดการหุ้น** → เพิ่ม `AMD`, `NVDA`, `PLTR`, `TSM`, `AVGO` (ระบบคำนวณแนวรับให้ทันที และใช้ตรวจว่า symbol ถูกต้อง) → กด **ส่งข้อความทดสอบ**

### 6. ตัวตั้งเวลา: cron-job.org (หลัก) + GitHub Actions (สำรอง)
**ทำไมไม่ใช้ GitHub Actions อย่างเดียว:** งานตามเวลาของ GitHub เริ่มช้ากว่ากำหนด 5–7 ชั่วโมงเป็นประจำ (วัดจริงช่วง 30 ก.ย.–5 ต.ค. 2026: รอบเช็กระหว่างวันเกือบทุกรอบไปเริ่มหลังตลาดปิดแล้ว) จึงใช้ [cron-job.org](https://cron-job.org) (ฟรี ตรงเวลาระดับนาที เลือก timezone ได้) เป็นตัวหลัก และเก็บ workflow ของ GitHub ไว้เป็นสำรอง — ส่งซ้ำไม่ได้ เพราะแต่ละรอบบันทึกไว้ใน `job_runs` และแจ้งเตือนถูก claim ไว้

endpoint ทำงานทั้งหมดในการเรียกครั้งเดียว (ดึงราคา/คำนวณทีละชุด 8 ตัว ห่างกัน 1 นาทีเอง) และ `?async=1` ตอบ `202` ทันทีแล้วทำงานต่อเบื้องหลัง (cron-job.org รอคำตอบได้ไม่นาน) ผลลัพธ์ดูได้ที่ Vercel → Logs

สมัคร cron-job.org แล้วสร้าง 3 งาน (Create cronjob) ทุกงานตั้ง:
- **Request method:** `POST` · **Headers:** `Authorization` = `Bearer <ค่า CRON_SECRET>` (แท็บ Advanced)
- **Time zone:** `America/New_York` (DST จัดการให้เอง ไม่ต้องมีรอบเผื่อ) · **วัน:** จันทร์–ศุกร์ (วันหยุดตลาด endpoint ข้ามเอง)

| งาน | URL | เวลา (นิวยอร์ก) |
|---|---|---|
| เช็กรอบเช้า | `https://<APP_URL>/api/cron/check?mode=daily&async=1` | 10:31 (= 21:31 / 22:31 น. ไทย) |
| เช็กรอบบ่าย | `https://<APP_URL>/api/cron/check?mode=daily&async=1` | 13:31 (= 00:31 / 01:31 น. ไทย) |
| คำนวณแนวรับ + สรุปหลังปิด | `https://<APP_URL>/api/cron/recalculate?async=1` | 18:05 |
| เก็บข่าว | `https://<APP_URL>/api/cron/news?async=1` | ทุกชั่วโมง นาทีที่ 15 (**ทุกวัน** รวมเสาร์–อาทิตย์ เพื่อเก็บข่าวสุดสัปดาห์) |
| สรุปข่าวก่อนตลาดเปิด | `https://<APP_URL>/api/cron/news?mode=brief&async=1` | 08:30 (= 19:30 / 20:30 น. ไทย) จันทร์–ศุกร์ |

ทดสอบ: กด "Test run" ในงานแรก ควรได้ `202 {"accepted":true}` (ถ้าได้ 401 แปลว่า header ผิด) แล้วดูใน Vercel → Logs ว่ามีบรรทัด `check (async)`

## Push ขึ้น GitHub

Repo นี้ตั้ง `origin` = `https://github.com/extratha/stock-support-alert.git` ไว้แล้ว

```bash
# 1) login (ครั้งแรก) — ต้องเป็นบัญชีที่มีสิทธิ์เขียน repo ของ extratha
gh auth login                 # เลือก GitHub.com → HTTPS → Login with a web browser
gh auth status                # ตรวจว่า active account ถูกต้อง

# 2) สร้าง public repo (ข้ามถ้ามีอยู่แล้ว)
gh repo create extratha/stock-support-alert --public --source=. --remote=origin --description "US stock support-level alerts via LINE"

# 3) push
git push -u origin main
```
ถ้า `gh` login เป็นบัญชีอื่น (ไม่ใช่ `extratha`) จะสร้าง/push ไม่ได้ ให้ `gh auth login` ใหม่ด้วยบัญชี `extratha`
หรือเพิ่มบัญชีนั้นเป็น collaborator ของ repo ก่อน
